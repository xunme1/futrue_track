# 服务器运维常用指令

本文适用于本项目部署在 Ubuntu 服务器、项目目录为 `/opt/futrue_track`、由 FastAPI 在 **8000** 端口对外提供页面和 API 的场景。

> 生产环境没有独立的前端常驻进程：React 前端经 `npm run build` 编译至 `frontend/dist/`，由后端 FastAPI 同源托管。因此，“更新/重启前端”实际是**重新构建前端静态文件**；需要重启的是 8000 端口的后端服务。

## 1. 常规发布：拉取代码、构建前端、重启后端

先登录服务器后执行：

```bash
cd /opt/futrue_track

# 若此命令显示了意外的已修改文件，先处理它们，避免 git pull 因冲突中断。
git status --short

# 仅允许快进更新，避免服务器自动生成合并提交。
git pull --ff-only origin main
```

### 重新构建前端

项目使用 Vite 5，Node.js 必须为 **18 或以上**。若服务器使用 nvm，建议使用 Node 20：

```bash
cd /opt/futrue_track/web
source ~/.nvm/nvm.sh
nvm use 20
node -v

# package-lock.json 有变动、首次部署，或 node_modules 不存在时执行。
npm ci

# 产物写入 /opt/futrue_track/frontend/dist/
npm run build
```

如果本次提交没有修改 `web/package.json` 或 `web/package-lock.json`，并且现有 `node_modules/` 完整，`npm ci` 可以跳过，只执行 `npm run build`。

### 重启后端

若此前按 `future-track.service` 配置了 systemd 服务：

```bash
systemctl restart future-track
systemctl status future-track --no-pager
curl -fsS http://127.0.0.1:8000/api/health
```

若不记得服务名称，先查询，再将下列命令中的 `future-track` 换成实际名称：

```bash
systemctl list-unit-files --type=service | grep -Ei 'future|track|uvicorn'
```

健康检查应返回：

```json
{"status":"ok"}
```

浏览器页面如仍显示旧前端，请用 `Ctrl + F5`（或清除该站点缓存）强制刷新。

## 2. 下载并计算最新数据

数据流水线顺序固定为：**下载行情 → 计算信号 → 生成筛选榜单**。

### 更新全部日线

```bash
cd /opt/futrue_track

.venv/bin/python -m backend.pipeline.download --timeframe 1d
.venv/bin/python -m backend.pipeline.daily --timeframe 1d
.venv/bin/python -m backend.pipeline.screen --timeframe 1d
```

`download` 会以增量方式下载，并自动回扫最近一小段时间以覆盖供应商对近期行情的修订。不要在日常运行中使用 `--full`。

### 仅更新指定品种

以中证 1000 与沪深 300 指数为例：

```bash
cd /opt/futrue_track

.venv/bin/python -m backend.pipeline.download --symbols 000852.XSHG 000300.XSHG --timeframe 1d
.venv/bin/python -m backend.pipeline.daily --symbols 000852.XSHG 000300.XSHG --timeframe 1d
.venv/bin/python -m backend.pipeline.screen --timeframe 1d
```

品种代码必须已经存在于 `config/contracts.yaml`；首次运行新加入品种时会自动补齐历史数据。

### 同时更新日线与 4 小时数据

```bash
cd /opt/futrue_track

.venv/bin/python -m backend.pipeline.download --timeframe all
.venv/bin/python -m backend.pipeline.daily --timeframe all
.venv/bin/python -m backend.pipeline.screen --timeframe all
```

## 3. 每日定时任务与手动执行

日更脚本已封装日线下载、信号计算和榜单生成，并会读取服务器私有凭据文件 `/etc/future-track.env`：

```bash
# 手动执行一次，并在另一个终端观察日志
bash /opt/futrue_track/tools/refresh_daily.sh
tail -f /opt/futrue_track/data/logs/refresh.log
```

建议服务器时区为 `Asia/Shanghai`，并设为工作日 17:30 执行：

```bash
timedatectl
crontab -e

# 周一至周五 17:30，调用日线更新脚本
30 17 * * 1-5 /opt/futrue_track/tools/refresh_daily.sh
```

查看已配置的当前用户定时任务：

```bash
crontab -l
```

脚本使用文件锁防止重叠运行。如果日志出现“已有日更任务在运行”，无需重复启动。

## 4. 日志与排错

```bash
cd /opt/futrue_track

# 日更完整日志 / 最近 100 行
tail -f data/logs/refresh.log
tail -n 100 data/logs/refresh.log

# 后端 systemd 日志（最近 100 行）
journalctl -u future-track -n 100 --no-pager

# 实时跟踪后端日志
journalctl -u future-track -f

# 检查 8000 端口是否监听
ss -ltnp | grep ':8000'
```

### 常见检查项

```bash
cd /opt/futrue_track

# 确认 Python 虚拟环境可用
.venv/bin/python --version

# 确认前端构建产物存在
test -f frontend/dist/index.html && echo 'frontend build OK'

# 确认私有凭据文件权限与内容键名（不要把实际密钥粘贴到终端记录中）
sudo ls -l /etc/future-track.env
sudo grep -E '^(FUTURES_IFIND_USERNAME|FUTURES_IFIND_PASSWORD|FUTURES_RQDATA_LICENSE_KEY)=' /etc/future-track.env | sed 's/=.*$/=已配置/'

# iFinD Linux SDK 默认动态库路径
ls -ld /opt/ifind-sdk/bin64
```

`/etc/future-track.env` 应至少包含以下环境变量，且该文件不进入 Git：

```bash
FUTURES_IFIND_USERNAME='你的 iFinD 用户名'
FUTURES_IFIND_PASSWORD='你的 iFinD 密码'
FUTURES_RQDATA_LICENSE_KEY='你的 RiceQuant 许可证'
```

## 5. 仅重启服务（不更新代码或数据）

```bash
systemctl restart future-track
systemctl is-active future-track
curl -fsS http://127.0.0.1:8000/api/health
```

如果 systemd 单元不是 `future-track`，请替换为实际的单元名。

## 6. 一次完整的发布后检查清单

```bash
cd /opt/futrue_track
git log -1 --oneline
test -f frontend/dist/index.html && echo '前端构建完成'
systemctl is-active future-track
curl -fsS http://127.0.0.1:8000/api/health
tail -n 30 data/logs/refresh.log
```

注意：`data/`、`config/config.yaml`、`/etc/future-track.env` 都是服务器私有运行数据或凭据，不应提交到 Git，也不应被 `git pull` 覆盖。

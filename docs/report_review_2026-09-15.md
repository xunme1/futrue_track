# 两份日报的效果评估与优化要点

评估对象：`data/reports/daily_report_2026-09-15.html` 与 `daily_report_2026-09-16.html`，分别对应9月14日和9月15日数据。同时核对同名JSON、当前生成器与新增的模型叙事程序。

本次是分析建议，不修改已有生成逻辑。工作区已有尚未提交的生成器、模型接入和测试改动，均保留。第一轮依据HTML内容与CSS、结构化事实、生成代码评估；随后根据用户提供的本地前端地址，通过看板“日报”入口实际预览了9月16日报告。已检查当前桌面窗口的首屏、滚动、优先表、回踩表和排名展开效果；窄屏与打印仍未实测。浏览器实看补充见第7节。

## 结论

当前报告仍以数据归档为中心。阅读者需要自己从大量状态和价格中挑出事件，再判断重要性；AI主要把字段压缩成短句。下一版应围绕“今天发生什么重要变化、证据是什么、和昨天判断有什么不同、接下来验证什么”组织内容。

9月15日报告使用规则文案，9月16日报告使用外部模型叙事，两份数据日期、字段覆盖和生成逻辑也存在差异，因此不能把两份差别全部归因于模型。可以明确评价的是：接入模型后，9月16日版仍存在术语泄漏、选择失焦和缺乏跨日解释的问题。

## 2. 首屏应呈现哪些真正重要的事

以9月15日数据为例，下面这三条比“25个重点标的”更适合作为摘要：

**多头预警继续兑现，橡胶三品种集体平多。** 日线多头25→19；前日7个多转空预警中，丁二烯橡胶、20号胶、天然橡胶、PVC、豆油5个今日出现日线平多，鸡蛋另新增平多。剩余预警标的是豆粕、国际铜。这里要表达“预警兑现到平多”，不能写成“全部开空”。

**乙二醇修复，欧线转弱，短周期表现继续分化。** 乙二醇4h于9月15日15:00开多、恢复双级别持多，日线名次9→5；欧线同一时刻4h平多、日线仍持多，名次13→17。两者反向变化支持“局部修复与局部转弱并存”，还不能据此推断整个能源化工板块完成轮动。

**遇压观察应把纸浆和多晶硅提到前面。** 两者现价已在各自日线压力带内，具备当下位置上的观察价值；是否出现受阻、突破或进一步确认仍要看后续行情。历史触压次数多但现价离压力带较远的品种可以保留在次级列表。

这三段只是基于已有技术快照的写作示范，不加入新闻因果、胜率或必然性判断。第一条的预警转化率是本次样本描述，不是策略胜率。

## 3. 视觉和信息结构：让变化比表格更先被看到

建议首屏采用“结论—事件—验证点”的阅读顺序：

1. **一句结论标题**：例如“多头预警兑现，橡胶集体平多；乙二醇出现局部修复”。日期在副标题明确写“9月15日收盘 / 9月16日观察”，降低报告日与数据日混淆。
2. **三张事件卡**：预警兑现、修复、当前临界位置。每张只放中文事件、代表品种、2项关键证据和“为什么重要”。数量服务于事件，不能只显示大数字。
3. **多空结构条**：日线多19、空24、观望25；4h另展示自身结构。配上一期变化，不把两周期混成同一比例。若有未知状态单独显示，不能算作观望。
4. **最多6个优先事件**：按“今日新增”“预警兑现”“修复”“临界待确认”组织。多个品种属于同一板块事件时合并事件卡，展开后仍一品种一行。
5. **最后才是全量明细**：历史信号、公式、所有关键位、数据来源继续可查，但退出首屏的注意力竞争。

具体视觉规则：

- 红橙用于“风险兑现/进一步转弱”，青绿用于“修复/改善”，灰色用于延续及待确认；始终伴随中文标签，不能只靠颜色。
- 用“新增”“升级”“修复”“延续”标签表达变化。多空用独立的“日线多/空/观望”标记，避免颜色同时承担方向和风险两套意义。
- 当前CSS中正文表格和分析段主要为12px。建议正文分析14–16px、表格13–14px，事件标题18–22px；这些是设计目标，仍需真实浏览器验证。
- 关键价位用横向位置条呈现“支撑带—现价—压力带”。清晰标注周期，现价超出图域时标示方向与实际距离，避免把不同价格跨度强行画成相同程度。
- 普通表格减少重复句，把“今日变化”“判断依据”“确认/失效条件”作为主列。代码、完整交易时间、重复价位移到展开层。
- 近7日趋势使用带日期的迷你折线或柱形图；数据不足时显示真实跨度。绝不把不同计算口径拼成一条连续曲线。
- 当前两份HTML各有15张表，HTML中含表头的tr数量分别为278、261，虽有折叠，重复阅读量仍大。减少主文重复，不仅是增加折叠按钮。

## 4. AI分析浅的根因

**任务定义限制了分析深度。** 当前把模型定义为“短评编辑”，大多数栏目限定120字，并规定优先复述现成分类。这样的任务可以得到合规短句，却难以形成有证据的判断。

**提供的跨日上下文不足。** 程序内部持有前日数据，但分节模型主要收到当日instruments；overview另有总数变化，rank另有排名轨迹。模型没有系统拿到每个标的昨日状态、score变化、历史关注理由、预警是否兑现，所以不容易回答“今天为什么特别”。

**七个孤立的栏目没有共同主线。** 当前逐节调用互不共享判断结果：一个栏目写修复，另一个继续沿用风险；模型容易重复规则或者在分类上自作解释。缺少统一事件清单、总论点和最终一致性检查。

**输入字段过多，任务又过短。** 把大量原始标的字段塞进上下文，再要求120字，模型容易选择压缩字段名、用合约代码堆叠，而不是花篇幅说明逻辑。

**质量检查偏向格式。** 当前核验了日期、指纹、长度与HTML边界，但没有检查是否有技术术语泄漏、是否存在未获证据支持的“反弹”，或重点卡是否漏掉当天事件。`evidence_keys`仅能指向标的，不能证明具体结论，而且合并后的展示数据没有保留其完整审计关系。

因此，第一优先级不是增加temperature或更换模型，而是重做输入事实与输出任务。模型选择可以在固定同一事实包后再评估。

## 5. 建议的分析流程与提示词方向

不需要一开始增加更多模型调用。建议改成“代码事实 → 综合分析 → 成品编辑/一致性复核”，单品种深读仅针对值得解释的少量事件。

### 代码事实层：先构建事件，提供可比较的证据

新增 `event_ledger` 和 `daily_diff`：包含标的中文名、前后持仓、前后交易信号、事件时间、前后价格与score、名次及榜单规模、前后关键位、价格穿越旧关键位与当前关键位的位置、命中原因、证据缺失情况。保存 `observed_at`、`data_date` 和规则版本。

把事件分类为“新开多/空”“新平多/空”“前日预警兑现”“双周期修复”“日线未变而4h转弱”“当前进入关键价位带”“排名变化但绝对动量未改善”。这些由程序计算，模型负责解释重要性。

历史关注结果至少区分兑现、修复、仍待确认；不能因为某个标签当天消失就写风险解除。仅一个4h开多若缺乏此前平仓证据，也不能自动叫“重新开多”。

### 综合分析提示词建议

> 你是期货技术日报分析编辑。依据已校验的事件表与前后日事实，选出3个最值得读者先看的变化。每个判断必须回答：发生了什么；有哪些至少两项不重复计算同一现象的证据；相反或削弱该判断的证据是什么；后续满足什么已给定条件才能确认或使当前判断失效。区分观测事实、解释和未确认情景。不得把平仓写成反向开仓，不得把排名提升单独写成主动走强。没有数据时说明需要哪项数据，不补造新闻或概率。输出结构化claims，每条含title、event_ids、evidence_refs、interpretation、counter_evidence、confirmation、invalidation、missing_data。保留内部引用，但对读者的文本只使用中文术语和品种名称。

每个重点事件可给150–250字的分析预算；首屏摘要再独立压缩到60–90字。长短分层，不要求整个分析步骤一开始就挤进120字。

### 单品种分析提示词建议

> 对给定重点事件解释“现象为什么值得关注”。比较前后日绝对动量、同榜相对位置、日线与4h状态、当前关键位。若名次提升但价格/score未改善，明确是被动上移或证据不足；若短周期修复而日线未确认，分别说明，不合并为转势。只使用程序提供的阈值。输出观察事实、解释、反证、下一步确认条件各一段；每项绑定具体证据引用。不得重复全市场通用规则填充字数。

### 成品编辑与一致性复核提示词建议

> 将分析结果写成可直接阅读的日报：先给今日三件事，再给优先观察卡，再给板块和个股解释。中文品种名为主，代码为辅。删去long_trend、risk、weak、repaired、hits等字段名及“可以写”“证据仅”等元说明。逐条检查观点与证据是否一致、同一标的各栏目有无矛盾、标题是否夸大、当日重要事件是否遗漏。发现不成立的观点，返回对应claim_id和需要修改的句子；不能只输出“校验通过”。

确定性检查应先于模型审核：阈值、方向、日期、价格关系、事件集合由代码核对；语义编辑交给模型，不能让模型自行批准与事实冲突的结论。

## 6. 实施顺序与验收目标

| 优先级 | 修改范围 | 验收目标 |
| --- | --- | --- |
| P0 | 事件检测、风险原因、当前支撑/压力扫描、历史轨迹日期 | 乙二醇修复/欧线转弱不漏；纸浆/多晶硅进入当前压力观察；曲线有截止日期；每个重点有真实原因 |
| P0 | 前后日事实包与语义校验 | 能识别国际铜被动升名次；不会仅凭4h观望说反弹；正文没有内部字段名 |
| P1 | 三张事件卡、状态条、事件优先表、价位位置图 | 目标为5秒看出3件重要变化、30秒找到关注品种的验证条件；需实际阅读测试确认 |
| P1 | 综合分析和成品编辑两阶段 | 每条判断有事实、解释、反证和验证条件；同品种各栏目一致 |
| P2 | 昨日关注结果、同批进场的完整生命周期、板块历史变化 | 能追踪当初同批成员的平仓和退出；不只统计仍留榜的幸存成员 |

同批进场目前只分组当前仍持仓的标的，已退出的成员不在分母中，不能由此判断整批趋势健康。应保存最初成员及后续退出记录，避免幸存者偏差。受压指标也应区分“进入压力带”和“已经突破压力上沿”，而不是把所有高于KK的价格都写成“带内”。

另外，9月15日报告缺失21个日线标的的部分关键位，9月16日报告已补充更多数据。不能直接把“重点10→25”全解释为行情恶化，应在一致字段覆盖与规则版本下重算历史后再比较。

代码定位：`backend/pipeline/generate_report.py` 的 `compute_facts`、`make_sections`、`PROMPT_TASKS`、`prompt_package`、`merge_narrative`；模型编排位于 `backend/pipeline/report_narrator.py`。建议先完成P0再处理P1，避免漂亮的版面强化不准确或缺失的结论。

## 7. 看板内实际预览补充

预览路径：`http://127.0.0.1:8765` → “📰 日报” → 当前选中2026-09-16。检查窗口为1280×720。页面DOM读取得到日报iframe尺寸约910×527，外层日期列表CSS固定250px宽。

### 首屏的信息分配有问题

实际首屏显示：深色标题横幅、导航、三张统计卡。具体品种、市场温度表和优先事件均位于下方，无法不滚动直接读到。标题区重复日期和程序化摘要，约占报告可视高度的四成；三张卡又只给数量，首屏没有回答“今天最值得看的是哪几件事”。

应优先提供独立报告页或全屏阅读模式，把日期列表收成可展开的目录或顶部日期切换。压缩标题区，首屏至少完整展示三条有品种名称的事件结论及一个验证点。不能只把日报HTML加宽，因为外层弹窗与侧栏仍会限制宽度。

相关代码：`web/src/components/ReportModal.tsx`、`web/src/App.css` 的 `.report-panel`、`.report-list`、`.report-viewer`，以及生成器的 `.masthead`、`.cards`。因此下一轮版面优化需要同时覆盖看板阅读容器与报告HTML。

### “重点”的视觉差异几乎被抹平

优先表实际显示为八行近似相同的“重点 / 品种”文字和左侧橙线，日期新旧、事件类型、当前是否仍持多都没有视觉编码。八行条件重复，肉眼扫过时难以停在某个特别重要的事件上。

问题不是颜色不够鲜艳，而是同一级样式覆盖了不同性质的状态。应先拆出“今日平多”“旧风险延续”“短周期修复”等事件，再用标签、左侧边线和关键数字突出差异。已平仓旧状态可继续归档，但不应自动挤占所有首页位置。

### AI分析看起来像表格脚注

回踩和排名栏目中，AI文本位于标题下方，使用与口径说明相同的小号灰字；一段话紧接长表格，没有明确的结论标题与证据分层。即便内容改好，用户也很容易略过。

建议改为“分析结论”区域：一句醒目的中文结论；下方两条证据；再下一行是条件或反证。字号和对比度高于说明文字。像“4h仍多但weak”“排名为score派生”这种规则或内部表述应改成清晰中文，并按需要收入口径说明。

### 关键价位比辅助日期更难扫读

回踩表在当前嵌入宽度下，历史触碰日期占据较宽列，最右侧“条件失效线”却折成两行，比较符号与价格分离。当前四个可完整看到的前排标的都是“带上方”，视觉又完全相似，无法快速判断距离远近。

应优先分配空间给现价、距关键位、确认/失效条件；历史次数和日期降到第二行或详情。关键比较与价格尽量保持同一行。位置条可以帮助比较，但仍应同时保留准确数值与周期。

### 排名表有数字变化，没有变化的视觉解释

实际页面中“新入榜”、+6、-4、+4和常规文字颜色接近；长串“— → — → …”占据大量空间。乙二醇的修复证据与国际铜的被动升名次没有差别呈现。

建议将排名变化单独成标签，空缺轨迹显示“历史不足”，轨迹有日期；另增“主动增强 / 被动上移 / 证据分歧”的解释，但分类必须由价格、动量和榜单变化共同支持。

### 已确认正常的部分

导航点击“优先关注”“龙头回踩”可以定位；点击“排名雷达”能定位并自动展开该节。固定导航正常，没有观察到这几个入口失效。当前桌面表格总体对齐，主要问题是信息优先级、嵌入空间和文字层级，不应把它概括为页面整体排版损坏。
